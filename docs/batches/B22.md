## 第一部分：压缩上下文（按钮 + 气泡）

### ① ★ 三种 reason 的准确语义（用户问的 ✓）

用户原话 ✓：
> "这个溢出指的是什么？这个溢出是报告一下，然后阻止当前的 prompt，
>  或者说截断了 AI 的流吗？"

**实测自 pi 源码**（`dist/core/agent-session.js:1655` ✓）：
```js
const contextOverflow   = isContextOverflow(assistantMessage, contextWindow);   // 超窗口
const recoverableLength = isRecoverableLength(assistantMessage, maxTokens);    // 被截断
if (contextOverflow || recoverableLength) {
    const willRetry = assistantMessage.stopReason !== "stop";
    if (this._overflowRecoveryAttempted) { /* ★ 只能救一次 ✗ */ }
    this._overflowRecoveryAttempted = true;
    // ★ 把那条失败的 assistant 消息从【重试上下文】里剔除（但留在历史里 ✓）
    this.agent.state.messages = messages.slice(0, -1);
    return await this._runAutoCompaction("overflow", willRetry);
}
```

**结论** ✓：
```
manual    → 用户点了按钮 ✓
threshold → ★【提前预防】✗ 上下文用量到阈值就自动压 ✓ 什么都不打断 ✓
overflow  → ★【已经出事了】✗ AI 的一次响应【超窗口失败】或【被 maxTokens 截断】✓
             pi 的救场三步：① 剔除坏消息 ② 压缩 ③ ★【自动重试一次】✓
             → 用户的 prompt 不会丢 ✓ 会重跑 ✓
             → 只有"重试也失败"才带 errorMessage（那时才是真失败 ✓）
★ 所以 overflow 【不是"主动阻止"】✗ 它是【事后救场】✓
```
