## B14

### ① ★ 自持传输层落地（B13 决策的执行）

**新建 `src/pi/rpc-client.ts`**（约 270 行，纯传输层）：
```
· spawn 子进程：node <cli.js> --mode rpc <额外参数>
· stdout 逐行解析（TCP 流会截断 → 必须自己拼行 ✓）
· pending 表：id → { resolve, reject }，请求超时 30s
· stop：SIGTERM → 1s 宽限 → SIGKILL
· ★ 进程退出时让所有挂起请求【立即失败】（不干等 30s 超时 ✓）
```

**★ 三个出口（这就是自持的全部价值 ✓）**：
| 出口 | 官方 | 我们 |
|---|---|---|
| `send(command)` | private ✗ | **public ✓** |
| `onStderr(cb)` | 只有拉取式 getStderr ✗ | **事件式 ✓（订阅时自动补发历史 ✓）**|
| `reply(response)` | 完全没有 ✗ | **有 ✓（写 stdin，不等回执 ✓）**|

**`src/pi/client.ts` 的改动**：
```
· import 换源（RpcClient → OwnRpcClient）
· ★ 删掉 attachStderr / emitStderr（绕私有字段的代码 ✗）
· ★ 删掉 replyExtensionUi 里绕 this.process 的代码
· onStderr 改为"记住订阅者 + client 重建时重挂"✓
· 新增 sendRaw()（发任意命令拿回执，不用改分派表 ✓）
· 删除 getStderr()（没人用 ✓）
```

**★ 一个意外收获：传输层不再依赖 `vscode`** ✓
```
原因：把日志改成【注入式】（logger 通过构造函数传入 ✓）
→ rpc-client.ts 只用 node 内建模块 → ★ 不启动 VS Code 就能单独测 ✓
→ 所以有了 scripts/smoke-own-rpc.mjs ✓（以前做不到 —— 它 import logger → logger import vscode ✗）
```

**冒烟结果**（`node scripts/smoke-own-rpc.mjs --ext`）：
```
✓ start
✓ getState 回执（请求-回执链路通）
✓ onStderr 回调 2 次 / 167 字符   ← ★ 事件式生效
✓ 事件类型: extension_ui_request   ← ★ 事件分发也通
✓ stop 干净退出
```

**私有字段依赖清零** ✓：`grep "unknown as" src/pi/` → 只剩注释 ✓

### ④ 配置：工具结果收起时两头露 N 行

```jsonc

"pi-bridge.style.toolPeekLines": "3:2"  // 开头 3 行 : 末尾 2 行

```

**实现取舍（重要）**：
```
part-text 里存【两份 DOM】：
  .part-full  全文        → 展开时显示
  .part-peek  头+提示+尾  → 收起时显示（…已折叠 N 行 ✓）

★ 为什么不共用一份 + CSS 裁切？
  CSS 只能"裁掉"，没法把裁掉的中间"补回来" ✗
  → 要同时支持"收起露两头 / 展开看全文"，就必须两份 ✓（文本量小，代价可忽略 ✓）

★ 只影响【结果文本】：参数（args）不受影响 ✓（它保持每行单独可折叠 ✓）
★ 原有行为（收起 = 整个结果区隐藏）在【未配置时】完全不变 ✓
```

### ⑤ ★ 配置实时生效框架（本轮最重要的架构改动）

**问题**：参数有几十个，但只有"纯样式"类改完立刻生效 ✗
（`toolPeekLines`、默认折叠等改完【必须重载】才看到 ✗ → 等于没法调参数 ✓）

**分层诊断**：
```
【第①类】纯样式（颜色 / 尺寸 / 圆角 / 字号）
  → ★ 天生实时 ✓（CSS 变量是"活的"，改了就重算 ✓）

【第②类】影响 DOM 结构（toolPeekLines / defaultThinkCollapsed）
  → ★ 不实时 ✗（已渲染的 DOM 结构是"死"的 ✗）→ 需要【重画】✓

【第③类】影响数据流（debug.collapse）
  → ★ 已经解决 ✓（调试板自己用 replayHistory 重放 ✓）
```

**统一动作 = 「重放」**（把已有能力接上，不是新机制 ✓）：
```ts
// apply.ts
let lastSnapshot = null;    // 记住最近一次快照
let replayPending = false;  // 待重放（流式中改配置时）
let agentBusy = false;

function replayForConfig() {
    if (lastSnapshot === null) return;
    if (agentBusy) { replayPending = true; return; }  // ★ 延后
    replaySnapshot(lastSnapshot, { keepNotices: true });
}
```

**三个必须说清的取舍** ⚠：
```
① 流式中改配置 → ★ 延后（记住待办，agent_settled 时空闲再重放 ✓）
   避免打断正在生成的气泡 ✗

② ★ 重放不该清空通知（通知是数据，不是渲染 ✗）
   → 新增 opts.keepNotices ✓
     · webview 重建 → resetNotices（用快照重建 + 默认收起 ✓）
     · 配置变化   → renderNotices（保留现有 ✓）

③ 要不要"按配置项精确决定重放范围"✗？
   → 不做 ✗。一律重放 ✓（气泡不多，开销可忽略 ✓）换取"心智一致"✓
```

> ★ 重放 = B1 就做好的能力（webview 重建时一直在用 ✓）
> 本轮只是把它【接到"配置变化"上】✓ —— 属于"复用"，不是"造新轮子"✓
