## 第一部分：★ 扩展交互回复桥（核心）

### ① 协议全貌（9 个 method ✓）

```
【需要回复的 4 个】→ 我们回 extension_ui_response
  select   { title, options: string[], timeout? }   回 { value }
  confirm  { title, message, timeout? }             回 { confirmed }
  input    { title, placeholder?, timeout? }        回 { value }
  editor   { title, prefill? }                      回 { value }
           ★ 注意：editor 【没有 timeout】✗

【单向的 5 个】（不需要回复 ✓）
  notify           { message, notifyType? }        ✓ 早已处理（通知板 ✓）
  setStatus        { statusKey, statusText }       ★ 实测你环境有：profile / catppuccin-tui / mcp
  setWidget        { widgetKey, widgetLines?, widgetPlacement? }
  setTitle         { title }                       ★ 对 VS Code 无用 ✗（它有自己标题 ✓）
  set_editor_text  { text }                        ★ 类我们已有的"注入输入框"✓

【回复的三种形状】
  { id, value }        ← select / input / editor
  { id, confirmed }    ← confirm
  { id, cancelled }    ← 取消
```

### ② ★★ pi 侧怎么接（源码实测 ✓）

```js
// rpc-mode.js:618
if (parsed.type === "extension_ui_response") {
    const pending = pendingExtensionRequests.get(response.id);
    if (pending) { pending.resolve(response); }   // ★ 用 id 匹配 pending 表 ✓
    return;                                       // ★ 不回执 ✓
}
★ 关键：响应是【顶层 type】✗ 不是包在参数里 ✓
★ 所以不能走 send()（会挂到 30s 超时 ✓）→ 用 reply() 直接写 stdin ✓

【pi 侧的解析规则】（rpc-mode.js:83 ✓）
  select:  cancelled → undefined | value → 字符串
  confirm: cancelled → false     | confirmed → 布尔   ★ 默认 false ✓
  input:   同 select ✓
  超时 → 各自 defaultValue（select/input = undefined ✓ confirm = false ✓）
```

### ③ ★★ 实测：扩展的两种"玩法"（数据包分析 ✓）

```
【select 的两种用法】
  正规的：title 短 + options 是纯选项 ✓
  ★ 变通的（ask-user-question 扩展 ✗）：
     title 里塞富文本（换行 / 代码块 / 表格 ✓）
     options 里带 "Type something."（= 自由输入项 ✓）

【input 被拿来当多选】
  title: "[多选四项] （2/4）多选 + emoji 标签，勾一个？\n\n1. 🔴 红色…\n2. 🟢 绿色…"
  placeholder: "1,3"     ← ★ 它用 placeholder 告诉用户"输入编号，逗号分隔" ✓

★★ 结论（用户定的方向 ✓）：
   用户：“它不会针对这个插件做了一些 TUI 优化……而我们这里应该做的是通用的桥”✓
   → ★ 桥【只要如实表达协议】✗ 不猜扩展的意图 ✓
   → 而 UI 必须能容纳【长 title / 多选项】✗（否则等于没渲染 ✓）

【关于"分页"的澄清】
  用户看到 title 里有（1/4）（3/4）（4/4）以为要分页切换 ✓
  ★ 实际是【扩展连续问了 4 个独立问题】✗（每个都是独立 select ✓）
  → 我们的【排队机制】就是它要的 ✓ 不需要分页 UI ✓
```
