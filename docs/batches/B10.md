### ② 两个 bug 的真相（都和"我以为的原因"不同 ✗）

**✕ 关闭按钮没反应** —— 真因在**插件端** ✗：
```ts
// 前端只发指令、不做乐观删除 ✓
closeBtn → postMessage({ kind: "noticeRemove", id })
// 插件端 main.ts 收到后：
chatState.removeNotice(msg.id)     ← ★ 改了内部数组，但【不 emit】✗
// → 前端永远收不到"这条已删" → 看着就是"点了没反应"✓
```
**修复**：`removeNotice()` 里补 `this.emit({ kind: "noticeRemove", id })` ✓
> ★ 教训：**"前端只发指令、权威在插件端"** 这个设计要求**插件端每次变更都必须广播** ✗
> 否则两边镜像会静默不一致 ✗

**⧉ 复制按钮** —— **它本来就是好的** ✓
- 我一开始误以为 `navigator.clipboard` 在 webview 里被限制（其实**可用** ✓）
- 用户实测"剪切板有用"→ 把误改的代码**还原**成 `navigator.clipboard.writeText` ✓

### ③ 面板高度：从 `max-height` 改成 `height`（语义修正）

```
现象：用户调 noticePanelHeight "没动静"，而且觉得默认 40% "是假的" ✗

原因：我写的是 max-height ✗
  max-height = 【上限】→ 内容少时面板只有内容那么高（长不到 40vh ✗）
  → 调大看不出、调小也看不出 → 像"设置没生效" ✓

修正：改成 height（【固定高度】✓）
  · 拉下来就是那么高 ✓
  · 通知多了 → 列表区出滚动条 ✓

★ 顺带修了固定高度的副作用：
  固定高度后，"点击收起"热区会被内容顶出视野 ✗
  → 面板内部改纵向 flex：只有 #notice-list 滚动，⌃ 热区钉在底部 ✓
```

**配置描述也跟着改**：`"通知面板的【高度】（占视图高度的百分比）。拉下来就是固定这么高，通知多了出滚动条。"`
