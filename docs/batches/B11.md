## B11：reload + `launchArgs` 懒读

### ① 为什么先做这个

用户要在开发中**试不同的启动参数**（`--no-extensions` / `--no-tools` / …），
但发现：**参数在"刚进 VS Code 时"读一次就固定了** ✗
→ 想换参数必须重载整个 VS Code 窗口 ✗（太重）

**目标**：改完设置，点一下按钮，pi 就用新参数重启 ✓

### ② 根因：两层"构造时固定"

```
main.ts      激活时 getConfiguration("pi-bridge").get("launchArgs")  → 读一次 ✗
PiClient     构造函数接收 extraArgs 数组                              → 存一次 ✗
RpcClient    args 在【构造时】就定死（官方实现）                      → 改不了 ✗
```

**所以光改 main.ts 不够** —— `RpcClient` 本身也得重建 ✓

### ③ 改法

**`src/pi/client.ts`**：
```ts
// ① 不再接收"参数数组"，改收【读参数的回调】→ 每次启动现读 ✓
constructor(cwd, options: { cliPath?; readArgs?: () => string[]; extraArgs?: string[] })

// ② client 不再是 readonly 字段，改成每次启动【重建】
private client: RpcClient | undefined;
private buildClient(): RpcClient {          // 现读参数 + 新建 RpcClient
    const extraArgs = this.readArgs();
    const client = new RpcClient({ cwd, cliPath, args: ["--no-session", ...extraArgs] });
    client.onEvent(...);                     // 事件转发照旧挂上 ✓
    return client;
}
private async doStart() { this.client = this.buildClient(); … }

// ③ 新增 reload()
async reload() {
    const wasRunning = this.started;
    await this.stop();
    if (wasRunning) await this.ensureStarted();   // 本来没跑就什么都不做 ✓
}
```

> ★ **订阅关系不受影响**：`onEvent` / `onStderr` 挂在 `PiClient` 自己身上，
> 重建的只是内部 `RpcClient` ✓

**`src/main.ts`**：
```ts
const pi = new PiClient(cwd, {
    readArgs: () => vscode.workspace.getConfiguration("pi-bridge").get<string[]>("launchArgs", []),
});
```

### ④ reload 按钮（前端）

```
位置：输入区那一排（模型名右边 ⟳）—— 和"发送"同一排 ✓
点击 → postMessage{reloadPi}  → main.ts 拦截（本地消息，不发 pi ✓）
     → await pi.reload()
     → ★ 同时清空前端：
         pi 换了新进程 → 它【不认识旧对话了】✗
         前端若还挂着旧气泡，接着聊会上下文对不上 ✗
         → chatState.reset() + 推空快照（前端重放=清空 ✓）
```

**顺手**：模型名改 `flex: 1`（占满左侧）→ 按钮自然被推到右端 ✓

### ⑤ ★ 崩溃修复：`Cannot read properties of undefined (reading 'process')`

**现象**：扩展激活失败，webview 渲染不出来（还没发消息就崩 ✗）

**根因**：
```ts
private client!: RpcClient;                 // ← ! 是"我保证有值"的断言，骗过了编译器 ✗
this.client = this.buildClient();            // ← 只在 doStart 里赋值
// 但 onStderr() 在【激活时】就被调用（main.ts 里）
// → attachStderr() 读 this.client.process → undefined.process ✗
```

**修复**：`client: RpcClient | undefined` + 各处判空 ✓
```ts
const client = this.client;
if (!client) { if (!silent) logError("pi 尚未启动"); return; }
```

> ★ **教训**：**用 `!` 断言绕开类型检查的代价** —— 编译器本该拦住的错误变成了运行时崩溃 ✗
> 应当如实声明 `| undefined`，让 TS 强制检查 ✓

### ⑥ 验证方式

② 点 ⟳ → 日志里应出现「额外启动参数: --no-extensions」✓

### ⑦ ★ 重要发现：`extension_ui_request` 一共 9 种 method

之前只见过 `notify` / `setStatus` 两种 ✗，查 pi 源码后拿到全集 ✓
（源码：`<pi 包>/dist/modes/rpc/rpc-mode.js` 里的 `createExtensionUIContext`）

| method | 字段 | 需回复？ | 我们现状 |
|---|---|---|---|
| `notify` | `message` + `notifyType` | ✗ | ✅ 已进通知板 |
| `setStatus` | `statusKey` + **`statusText?`** | ✗ | ❌ 未处理（**有文本可用 ✓**）|
| **`setWidget`** | `widgetKey` + `widgetLines` + `widgetPlacement` | ✗ | ❌ 未处理（扩展小部件）|
| `setTitle` | `title` | ✗ | ❌ 未处理（可设面板标题）|
| `set_editor_text` | `text` | ✗ | ❌ 未处理（可填输入框）|
| **`select`** | `title` + `options` | ★ **要回** | ❌ 未处理 |
| **`confirm`** | `title` + `message` | ★ **要回** | ❌ 未处理 |
| **`input`** | `title` + `placeholder` | ★ **要回** | ❌ 未处理 |
| `editor` | `title` + `prefill` | ★ **要回** | ❌ 未处理 |

**回复机制**（源码里 pi 把 Promise 存在 `pendingExtensionRequests` 等回）：
```json
{"type":"extension_ui_response", "id":"<同一个 id>", "value|confirmed|cancelled": …}
```

> ★ **`select` / `confirm` 就是【守卫扩展拦工具】的审批弹窗** ✓
> 做了它就能不靠 `--no-extensions` 跑工具了 ✓
