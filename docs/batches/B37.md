## 二、★ 面板"再点一次关不掉"（toggle）

### 现象（用户报的 ✓）

> "我打开绘画面板 ✗ 再点击绘画按钮 ✗ 关闭不了它
>  同样的道理另外两个面板也是一样的情况"✓

### 原因

```
B35 的 showExclusive 只有"开"的语义 ✗ 没有"关"✓
侧栏按钮 → open → showExclusive → show() → reveal()
⇒ 面板已经开着时，它是一个【空转】✓ 看起来就像"按钮坏了"
```

### 修法（★ 一个容易搞错的细节）

```
showExclusive(which, toggle = false)
  ★ 判断用 isVisible() ✗ 不是 isOpen()

  · 面板【就在眼前】（visible=true）→ 再点 = 关掉它 ✓
  · 面板【存在但被别的 tab 盖住】（visible=false）→ 再点 = 把它露出来 ✓
     ★ 只看 isOpen() 就会把"后台那个面板"直接关掉 ✗
       用户看到的是"点了按钮，什么都没出现，而那个面板不见了"✓ 很怪 ✓
```

**生效范围**：

| 入口 | toggle？ | 理由 |
|---|---|---|
| 侧栏 ☰ 会话 / ⚙ 设置 / 技能按钮 | ✅ | 它们就是"同一个开关"✓ |
| 命令面板 `Pi: 打开会话面板` 等 | ❌ | 那是"我要用它"的明确意图 ✗ 点了又关掉很怪 ✓ |

每个 Panel 类新增：`isVisible() { return this.panel?.visible ?? false; }` ✓

## 三、★ 补全"pi 发的"东西（用户定的范围）

### 用户定的边界（★ 很重要 ✓）

> "我们只要后端的呀 ✗ 只要 pi 的 ✗ 只要是 pi 发的我们都要。
>  我们发的就不要了。"✓
>
> "它就是进度表和防漏表 ✗ 有字段没消费 ✗ 我随时都能看"✓

```
✅ 进调试板：pi → 扩展宿主（事件流 / 回执 / stderr）
❌ 不进：  宿主 → pi（我们发的 RPC）
❌ 不进：  webview ↔ 扩展宿主
```

### ★ 查完的结论：已经【基本收全】了

`src/pi/rpc-client.ts` 的 `handleLine` 里有一句关键设计（B25 做的 ✓）：

```ts
// ① 回执：匹配 pending 则先 resolve（让调用方拿到 ✓）
// ★ 但【不 return】—— 还要广播给订阅者（调试板要看 ✓）
// ② 全部当事件广播（含回执 ✓）
```

⇒ pi 发的**回执 + 事件**全都进调试板 ✓（这也解释了为什么 test_date 的导出里连 `response` 包都有 ✓）

### 真正漏的两个边角（本轮补上 ✓）

| 漏洞 | 原来的样子 | 现在 |
|---|---|---|
| **stdout 里的非 JSON 行** | `catch { log.debug("忽略非 JSON 行") }` —— 只有输出面板看得见 ✗ | 广播 `pi_stdout_raw` ✗ 调试板也看得见 ✓ |
| **进程退出 / 启动失败** | 只变成 `exitError` ✗ 看不见 ✓ | 广播 `pi_exit` / `pi_spawn_error` ✓ |

新增类型 `PiLocalEvent`（`src/pi/rpc-client.ts` 导出 ✓），并放宽 `PiEventHandler` ✓

### ★ 两个关键位置（别改错 ✓）

```
① rpc-client 的 handleLine 【catch 里】也要广播 ✗ 不能只是 return ✓
② main.ts 里拦掉 pi_* 的那段【必须在 debugPanel.log(event) 之后】✗
   （B25 踩过同样的坑：写在 log 之前 → 调试板看不到 ✓）
```
