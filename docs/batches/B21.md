## B21

### ① 为什么先做菜单而不是直接做删除 ✓

用户原话 ✓：
> "删除绘画也放到那个右键菜单里面。不如先做右键菜单?"

**同意** ✓ —— 菜单是**容器**✓ 删除是**它里面的一项**✓
先做容器 → 后面加操作只是往数组里塞一项 ✓ 反过来做就要改两次 ✓

### ② ★ 通用右键菜单（`src/webview/context-menu.ts` ✓ 新文件）

**为什么自绘而不是用现成的** ✗：
```
· webview 里的原生右键菜单 = 浏览器的（刷新 / 检查元素 ✓）与业务无关 ✗
· VS Code 的 QuickPick = 顶部搜索框 ✗ 不是光标处弹出 ✗
· 而我们要的是"鼠标位置弹出一个动作列表"✓ → 自绘最简单 ✓
  （而且样式能跟主题变量走 ✓）
```

**实现要点** ✓：
```

         （viewport 坐标 ✓ 不受滚动影响 ✓）
· 边界翻转：先挂上去量尺寸 ✓ 再 Math.min 夹到窗口内 ✓（右下角不会出屏 ✓）
· 三种关闭：点菜单项 ✓ / 点外面 ✓ / Esc ✓
  ★ 点外面靠 document 上的 click 监听 ✓
```

**做成通用组件** ✓：


### ③ 删除会话（★ pi 没有接口 ✗ → 照抄官方 TUI ✓）

**调研结论** ✓：
```
· 42 个命令里【没有 delete_session】✗
· 但 TUI 里能删 ✓ → 因为它是【前端自己删文件】✓
  官方实现在 dist/modes/interactive/components/session-selector.js:541 ✓
```

**官方的做法** ✓：
```js
async function deleteSessionFile(sessionPath) {
    const trashResult = spawnSync("trash", [sessionPath], { encoding: "utf-8" });
    if (trashResult.status === 0 || !existsSync(sessionPath)) return { ok: true, method: "trash" };
    await unlink(sessionPath);   // 回落
    return { ok: true, method: "unlink" };
}
// ★ 两个保护（官方也有）：不能删当前会话 ✗ + 二次确认 ✗
```

**★ 我们做得比官方稳一点** ✓（实测发现的 ✗）：
```
官方【只试】`trash` 一个命令 ✗
而用户的 CachyOS（KDE）上【没装 trash-cli】✗ 只有 `gio` ✓
→ 照搬官方的话会【直接 unlink 永久删除】⚠
   而用户【以为自己进了回收站】✗☠ ← 这个误解很危险 ✓

我们的三级回退：
  ① trash      （trash-cli 包 ✓）
  ② gio trash  （GLib ✓ 大多数桌面环境都有 ✓ 你的机器就是走这条 ✓）
  ③ unlink     （⚠ 真删 ✓ 只有前两个都不可用才走 ✓）
★ 并【如实报告】走的哪条 → "已移到回收站（gio）"✓ / "已永久删除"⚠
```

**★ 实测验证** ✓：
```
/tmp 上 gio trash → ✗ 失败（"不支持在系统内部挂载上的丢弃到回收站操作"）
   原因：/tmp 是 tmpfs（内存盘 ✓）不支持回收站 ✓ 正常现象 ✓
真实磁盘上 → ✓ 成功

★ 而 pi 的会话文件在 ~/.pi/agent/sessions/（真实磁盘 ✓）
→ 所以【删会话会走回收站】✓ 可恢复 ✓
```

**实现** ✓（`session-store.ts` 的 `deleteSessionFile` + `main.ts` 的 `doDeleteSession` ✓）：
```
① 保护：是不是当前会话？→ 是就拒 ✓（pi 还抱着它的句柄 ✓ 删了会出怪事 ✓）
② 存在性检查 ✓
③ 原生 modal 二次确认（带完整路径 ✓）
④ trash → gio → unlink ✓
⑤ ★ 后端直接刷新列表（不等前端点 ⟳ ✓）
```

### ④ 导入 / 导出

**先确认接口** ✓：
```
export_html { outputPath } → { path }    ✓ 有
   ★ 但【只能导"当前会话"】✗（内部固定用 session ✓ 不接受 sessionPath ✗）
import_*                                  ✗ 【完全不存在】✗
→ 两个都得自己写 ✓
```

**好消息：pi 只认后缀** ✓：
```js
// session-manager.js 扫目录的规则
readdirSync(dir).filter((f) => f.endsWith(".jsonl"))     // ★ 就这一条 ✓
→ 不校验文件名格式 ✓ → 导入导出就是【纯文件复制】✓
```

**导出** ✓（`doExportSession` ✓）：
```
★ 用 QuickPick 选格式，而不是两个菜单项 ✗
理由① 不污染菜单（已经 4 项了 ✓）
理由② ★ 原生控件能写【说明文字】✗ 而这个差别【必须说清楚】✗：
        JSONL → 原始记录，可再导入回 pi（任意会话都可导 ✓）
        HTML  → ★ 只能导【当前会话】✗
理由③ 非当前会话时 HTML 那项【置灰 + 说明】✓ 不偷偷帮用户切过去 ✗
```

**导入** ✓（`doImportSession` ✓）：
```
外部 .jsonl → 【当前 cwd 的会话目录】✓
  为什么是当前 cwd？✓
    · pi 只认【cwd 对应目录】里的会话 ✗（TUI 列表也按 cwd 分 ✓）
    · 放错目录 → 以后在 TUI 里根本看不到它 ✗
· 同名不覆盖 ✗（加短后缀 ✓ 避免干掉已有会话 ✓）
· 导入后刷新列表 ✓
```

**★ 目录名的转义规则** ✓（导入必须知道 ✓）：
```js
// 来源：pi 的 dist/core/session-manager.js:242
const safePath = `--${cwd.replace(/^[/\\]/, "").replace(/[/\\:]/g, "-")}--`;
// /home/liuqingxue → --home-liuqingxue--
// /home/liuqingxue/Docs/简历 → --home-liuqingxue-Docs-简历--

★ 为什么自己实现而不 import 那个函数？
  它只从 dist/core/session-manager.js 导出 ✗（不在包主入口 ✓）
  走内部路径 import 会【随版本升级而断】✗
  而这条规则极简且稳定 ✓ → 自己实现 + 注明来源更方便日后核对 ✓
```

**★ 导入必须校验** ✗（用户要求的 ✓ 原话："不检验一下，不拦一下吗?"✓）：
```
判定规则（宽松但足够）：
  ① 后缀 .jsonl ✓
  ② 非空 ✓
  ③ ★ 首行是合法 JSON 且 type === "session" ✓
     （实测：pi 自己写的会话文件【第一行必是 session 头】✓
       带 cwd / id / timestamp / version ✓）

为什么必须拦 ✗：
  导入的是【外部文件】✗ 可能是任意 jsonl（日志 / 别的工具导出 ✓）
  不拦 → 变成一条【切不过去、还得手动删】的垃圾条目 ✗
    （切换时 pi 会报 "Session file is not a valid pi session" ✓）

为什么不全读 ✗：会话可能 10MB+ ✓ 而首行是 header ✓ 够用 ✓
```

### ⑤ ★★ 踩的坑：QuickPick 的 `disabled` 是【假禁用】✗

**现象**（用户实测报的 ✓）：
```
导出会话 → QuickPick 里 HTML 那项【确实是灰的】✓
→ 但点它【仍然能进入保存对话框】✗
→ 选完路径确认 → 文件没出现 ✗
```

**根因** ✗：
```typescript
// 我当时写的：
{ label: "导出为 HTML", disabled: !isCurrent }    // ← 只在 UI 层标灰 ✓
...
if (!pick) return;
if (pick.fmt === "jsonl") { …同步复制… }
// ★ HTML 分支【没有判断 isCurrent】✗✗ 直接弹保存框了 ✓
//   而 export_html 【固定导出当前会话】✗ 不管右键的是哪条 ✓
//   → 用户在非当前会话上测 → 导出的根本不是他点的那个 ✗
```

**修** ✓：
```typescript
// ★★ 这里必须【自己再拦一次】（不能只靠 QuickPick 的 disabled ✗）

    void vscode.window.showWarningMessage("HTML 只能导出【当前正在使用的会话】✗\n先切到它，再导出 ✓");

}
```

**★ 教训（写进 FACTS ✓）**：

```
UI 的禁用【永远不可信】✗ —— 它只是装饰 ✓
真正的约束【必须在逻辑层】再校验一次 ✓
```

**顺手排查** ✓：
```

  → 那是【真 HTML button 的 disabled】✓ 浏览器会拦 click ✓ 没问题 ✓
```

### ⑥ 一个虚惊：删了文件忘了删索引？✓

用户警觉地问 ✗：
> "我们那个有一个数据文件删会话的时候忘了删对应的条目了吧?"

**核实结果：其实已经有自动清理** ✓：
```typescript
// SessionStore.listEntries() 每次都会【重新扫盘】✓
const alive = new Set(out.map((s) => s.path));         // 本次扫到的路径
for (const p of Object.keys(this.data.files)) {
    if (!alive.has(p)) { delete this.data.files[p]; cleaned++; }   // ★ 死条目自动清 ✓
}
```
而 `doDeleteSession` 最后调了 `postSessionList()` → `listEntries()` ✓
→ **删掉的条目会被清掉** ✓ 没有这个 bug ✓

（不过这个警觉很对 ✓ "删了实体忘了删索引"确实是经典坑 ✓）
