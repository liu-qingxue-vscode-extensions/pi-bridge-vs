## 一、问题（用数字说清它到底乱在哪）

B36 之前，`handleFrontendMessage` 一个函数里塞了 **31 个分支**，
按"消息从哪来"分其实是四类混在一起：

| 类 | 分支 | 谁在发 |
|---|---|---|
| **A 聊天页专属** | `command*`(5) · `notice*`(2) · `webviewLog` · `listModels` · `listThinkingLevels` · `uiResponse` · `listCommands` · `interactionFocus` · `changeCwd` · `reloadPi` | 只有侧栏 |
| **B 会话领域** | `newSession` · `renameSession` · `openSessions` · `refreshSessions` · `switchSession` · `clone/forkSession` · `deleteSession` · `exportSession` · `importSession` | **侧栏和会话面板都发** |
| **C 设置领域** | `openSettings` · `reloadSettings` · `saveSettings` · `addApiKey` · `removeAuth` | 侧栏 + 设置面板 |
| **D 技能** | `openSkills` | 侧栏 + 技能面板 |

### 而"面板的消息去哪"有【两条不同的路】✗

```
路由 A：聊天页 → handleFrontendMessage（一个 800 行的 if 链 ✓）
路由 B：独立面板 → 构造时传进去的 onMessage 闭包 ✓
        ├ 转交型（会话 / 设置 ✗ B35 写的）
        │   回调里就一句 void handleFrontendMessage(payload)
        └ 自处理型（技能 / 命令 ✗ B31 / B32 写的）
            回调里自己写 if 链
```

**同一件事（"面板发来的消息"）有两个藏身处** ✗
⇒ 加逻辑时只要选错一条 ✗ 就是静默失效 ✓
⇒ **B35 我就是这么栽的**（详见 [B35 第七节](./B35.md) ✓）

## 二、设计：三层

```
① 接线层  src/main.ts
    只剩组装 + 生命周期：
      new XxxPanel(uri, createXxxHost({ ...deps }))
      const xxxActions = createXxxActions({ ...deps })
    ★ 2693 → 1962 行 ✓

② 路由层  src/panels/xxx-host.ts      ← 每个面板一个，"这个面板的消息"只在这里
    消息 → 动作的【映射】（一个 switch ✗ 一个 kind 一个动作 ✓）
    createSkillsHost    技能面板 7 个 kind
    createCommandHost   命令配置页 2 个
    createSessionHost   会话面板 7 个
    createSettingsHost  设置面板 5 个

③ 领域层  src/panels/xxx-actions.ts   ← 真正的逻辑，只在这里一份
    createSkillsActions    扫技能 / 打开 / 删除 / 隐藏 / 新建 / 注入 / 发送
    createSessionActions   列表 / 新建 / 改名 / 切换 / 分支 / 删除 / 导出 / 导入
    createSettingsActions  读写 settings.json / 凭据
    （命令配置页的保存动作留在 main.ts ✗ 它要用图标系统 ✓ 见下）
```

### 关键收益

```
★ "某面板的消息在哪处理"从此只有一个答案
  ⇒ B35 那种"加错通道 ⇒ 静默失效"结构上不可能再发生 ✓

★ 跨面板共用的动作【只有一份实现】
  侧栏「＋ 新建」→ sessionActions.newSession()
  面板「＋ 新建」→ 同一个 sessionActions.newSession()
  侧栏 ⚙ / 面板「重新读取」→ 同一个 settingsActions ✓

★ 每个 host 的 default 分支都 logWarn
  ⇒ 前端加了新消息但宿主忘了接 ✗ 输出面板立刻能看见 ✓
    （以前是"点了没反应"✗ 极难查 ✓）
```

### ★ 为什么命令配置页没有 actions 模块？

```
它的保存动作依赖【图标系统】（materializeIcon / removeIconFile ✓ B32/B34）
那是另一摊事 ✗ 硬搬会把图标系统也一起拖出来 ✓
⇒ 折中：路由进 command-host.ts ✗ 动作抽成具名函数 saveCommandDraft
  留在 main.ts ✓（顺手把匿名回调变成具名的 ✗ 报错栈里不再是 "(anonymous)" ✓）
★ 它【没有"两份"的风险】✗ 只有配置页一个来源 ✓ 所以够用 ✓
```
