## 二、键盘体系（本轮重头戏）

### ⑤ 用户定的规则（★ 边界穿越 ✗）

```
★ 输入框里的方向键是【光标导航】✗ 不能直接抢掉 ✓
   → 只有光标已经到边界、再按一下才“越界”到别的控件 ✓

↑  输入框在【首行】再按 ↑ → 进选项（最后一个 ✓）
↓  输入框在【末行】再按 ↓ → 进选项（第一个 ✓）
←  输入框在【最左】再按 ← → 上一页 ✓
→  输入框在【最右】再按 → → 下一页 ✓
```

### ⑥ ★★ 输入框 + 选项是【一个环】

```
↓ ： 1 → 2 → 3 → 【输入框】 → 1 → 2 → ...
↑ ： 【输入框】 → 3 → 2 → 1 → 【输入框】 → 3 → ...
```
即 `kbd ∈ {-1（输入框）, 0..n-1}` 一起循环 ✓ 回到输入框会自动聚焦 ✓

### ⑦ ★ confirm 页【不能】把“输入框”纳入循环

```
用户报：“刚开始啥也没选中 ✗ 按一下下到确认 ✗ 再下取消 ✗ 再下啥都没有 ✗ 再下确认”
根因：confirm 页【没有输入框】✗ 但我用了同一套循环 → 走到了 kbd=-1 ✓
修：confirm / editor 页 → 【纯选项环】✗ 确认 ⇄ 取消 ✓
```

### ⑧ ★★ 两个 keydown 监听器（最隐蔽的 bug ✗）

```
现象：★ 按一下 → 页码跳【两格】（用户实测 p0 → p2 ✓）
      按 → 直接跳过第 2 页 ✗ 按 ← 也要按好几下 ✓

根因：src/interaction/index.ts 里有两个 document.addEventListener("keydown") ✗
      ① 我新写的完整版（含 ↑↓←→ Enter Esc）
      ② ★ 之前那轮的“←→ 翻页”块 —— 没删掉 ✗

而且旧块还有个更隐蔽的问题 ✗：
  const last = history + queue + (batch ? 1 : 0);
  const clamped = Math.min(next, last);   // ★ 允许走到 total ✗
  → 那个位置是“虚拟等待页”✗ → 显示“等待下一个问题”✓

★ 定位方法：grep -c 'addEventListener("keydown"' media/interaction.js
   → 打包产物里应该是 3 个（index 1 + controls 1 + views 1）
   → 当时是 4 个 ✗ 一眼看出 ✓
```

### ⑨ ★★ 焦点在输入框里 → 键盘被“吃掉”

```
现象：★ 按 ↓ 选中第一个后再按 ↓ 无反应 ✗
      按 ← 要按好几下才切页 ✗ 而 → 却正常 ✓

根因：焦点【还在输入框里】✗ 但 kbd 已经 >= 0（在选项上）✓
   → ←→↑↓ 全被当成“光标导航”✗ 不在边界就不处理 ✓
   → ★ 不对称的原因：← 要求光标在【开头】✗ → 只要在【末尾】✓

修（两道保险 ✓）：
  ① 只有 kbd < 0（“输入框”那一环）才把它当输入框 ✗
  ② paintKbd() 里若 kbd >= 0 且焦点在输入框 → blur + body.focus() ✓
```

### ⑩ ★ 首尾循环（用户要求 ✓）

```
第 1 页按 ← → 跳到【最后一页】✓
最后一页按 → → 回到【第 1 页】✓
★ 但“虚拟等待页”（page == total ✗ 等下一题的位置）【不允许手动走进去】✗
   否则 page 越界 ✗ 下一题到达也 clamp 不回来 → “等待下一个问题”✓
```

```
⑲ /uitest        4 种交互串行（B25 就有 ✓）

㉑ /uitest-slow   ★ 串行 + 每问间隔 3 秒 × 4 回
   → 测：面板不闪 ✗ 页签从 [1] 长到 [1][2][3][4] ✗ 前几个变只读历史 ✓

   → 测：答卷模式页签 + 确认页校验 ✓
```

★ **"并发"的定义**（用户问过 ✗ 记下来 ✓）：
```
pi 协议里【没有批量包】✗ 每个 ui 请求都是一个独立包 ✓
“并发” = 扩展在收到答复前，一口气发了【多个独立包】✗
   → 我们的 pending 数组一次性变 N ✓ → 队列 >= 2 → 答卷模式 ✓
★ 对框架来说，串行与并发的处理【完全一样】✗ 只看队列长度 ✓
```
