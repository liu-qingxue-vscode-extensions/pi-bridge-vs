## 一、★★ 真懒加载（打开扩展 = 零进程）

### 现象

```
B42 做完"零子进程渲染"之后，我以为"打开扩展不启动 pi"也顺带成立了
（因为 onReady 里早就有 isStarted() 守卫 ✗ 未启动就只读 settings.json ✓）

但用户实测："我刚一打开通知就发过来了…这显然启动了呀"
★ 又一次印证：代码层面"看着有守卫"✗ 和"实际没启动"是两回事 ✓
```

### 定位方法（★ 值得复用）

**不要猜 ✗ 在怀疑的那一层打【调用栈】**：

```ts
// src/pi/client.ts 的 ensureStarted()（唯一的懒启动入口）
const st = new Error().stack?.split("\n").slice(2, 6)...
logInfo(`[PiClient] ★ 启动被触发，调用栈：...`);
```

**栈直接给出了答案**：

```
PiClient.sendRaw                          ← 有人发 RPC
ChatView.handleFrontendMessage [onMessage] ← ★ 是【前端】发来的消息
Cp.value (chat-view.js)                    ← webview 的 postMessage
x._deliver (extensionHostProcess.js)       ← VS Code 投递
```

### 根因：斜杠命令补全在【启动时】就预拉

```
src/webview/slash-menu.ts 两处：

① setupSlashMenu() 末尾：
     // ★ 首次进入主动拉一次 ✗（这样按 / 立刻就有 ✓）
     vscode.postMessage({ kind: "listCommands" });
   ⇒ 打开扩展就拉 → 宿主 get_commands（RPC）→ spawn pi ✓

② refreshSlashMenu()：
     if (commands.length === 0) { postMessage({kind:"listCommands"}); return; }
   而它由 inputEl 的【input 事件】触发 ⇒ 用户随便打个字也会拉 ✓
```

### 修法（用户定的："再让它再懒一点就好了。我如果敲斜杠的话，它就尝试补全然后启动"）

```ts
export function refreshSlashMenu(...) {
    const prefix = currentPrefix();
    if (prefix === null) { close(); return; }   // ★ 不是斜杠命令 ⇒ 一个请求都不发
    if (commands.length === 0) { postMessage({kind:"listCommands"}); }  // 真在打 / 才问
}
// setupSlashMenu：删掉"首次主动拉"
```

**验证**：用户确认"OK，似乎完美了。真正的懒加载了"✓
（现在：打开扩展 = 零进程 ✗ 敲 `/` 才拉起 pi ✓）

**★ 附带**：那句调用栈日志**留下**（降到 debug 级）—— 以后再出现"怎么自己启动了"，一看栈就知道是谁，比猜快得多。

## 二、剪掉「改会话目录」的入口

### 为什么危险

```
pi 的 --session-dir 原文是 "Directory for session **storage and lookup**"
   ⇒ ★ 一个值【同时管读和写】✗ 改了它 = 换了个库：
       新会话写到新地方 ✗ 旧会话看不见（因为不去旧地方找了）
   ⇒ 用户会觉得"我的会话凭空消失"✗ 对小白尤其危险 ✓
```

（B42 第四节已把它列为"前提 B"的一部分 ✗ 这里是落地）

### 做法

```
删掉 src/pi/settings-schema.ts「环境」组里的可写 sessionDir 条目
★ 我们仍然【按那条链解析】（pi-env.ts 的 resolveSessionRoot ✓）⇒ 行为完全不变
★ 想改的人：改 <agentDir>/settings.json，或环境变量 PI_CODING_AGENT_SESSION_DIR
  （那是懂自己在干什么的人 ✓）
```

## 三、只读探测目录（`pi-bridge.sessions.extraDirs`）

### 需求（两方面）

```
★ 用户需求："我有散落各处的会话（从别的机器拷来的 / 旧目录）✗ 都想看见"
★ 设计原则：只读扫描 ✗ 绝不碰 pi 的 sessionDir（那是"换库"✗ 这是"多看几个库"）
```

### 实现

```
① package.json：pi-bridge.sessions.extraDirs（string[] ✗ 默认 []）
② SessionStore.setExtraDirs() + roots() = 主目录 + extraDirs（去重）
③ ★ cwdMap / cwdKey 的键从【目录名】改成【完整路径】
     （不同根下可能有同名 cwd 目录 ✗ 用目录名会互相覆盖 ✓）
④ 额外目录读不到【不报错】（用户随手配的 ✗ 主目录才报 ✓）
⑤ main.ts：启动 / reload / 配置变化 时都重新注入
```

**副作用（记下来）**：`cwdMap` 的键变了 ⇒ **第一次会失效重读一遍**（旧键被清理逻辑删掉 ✗ 之后正常 ✓）。

**状态**：⬜ 未实测 —— 用户说"这个东西很难测呀…以后我再来详细读源码的时候再来做完整测试"✓
