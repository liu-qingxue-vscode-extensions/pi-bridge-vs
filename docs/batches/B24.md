## 第一部分：★ 会话树（fork 渲染）

### ① 数据从哪来（实测 ✓）


### ② 前端 `treeify()`（`sessions.ts` ✓）

```typescript
// 输入：同一 cwd 的一组会话
// 输出：DFS 扁平化 [{ s, depth }]（父后面紧跟它的子 ✓）
const byPath = new Map(items.map((s) => [s.path, s]));
const kids = new Map<string, SessionInfo[]>();
for (const s of items) {
    if (s.parent && byPath.has(s.parent) && s.parent !== s.path) {
        (kids.get(s.parent) ?? kids.set(s.parent, []).get(s.parent)).push(s);
    } else roots.push(s);       // ★ 边界①：parent 不在同组 → 当根 ✓
}
// DFS + seen 兜底（★ 边界②：环，理论上不会但损坏文件可能 ✓）
```

**★ 两个边界必须处理** ✗：
```
① parent 指向的会话【不在同一组】✗（跨 cwd / 已被删除 ✓）
   → 把它当【根】✓ 否则【整条会消失】✗
② 环（A→B→A）—— 正常不会 ✗（父总是先创建 ✓）
   但加载到被改坏的文件就可能 → seen 集合兜底 ✓
```

### ③ ★★ 踩的坑 1：parent 在成功路径上丢了 ✗

```
现象：前端【完全看不到任何分支】✗（平铺如常 ✓）
根因：readNameAndCheck() 有【三处 return】✗
   ① 判异常 → return { broken }        ✓（不需要 parent ✓）
   ★② 找到名字 → return { name }        ✗ 没带 parent ✓
   ★③ 没名字   → return {}             ✗ 没带 parent ✓
   → 成功路径把 parent 丢了 ✓ → 缓存 88 条全部缺 parent ✓

★★ 而且 TypeScript 【抓不到】✗ —— 因为 parent 是【可选字段】✗
   （可选字段缺失是合法的 ✓ 类型检查不会报 ✓）
★ 教训：给可选字段赋值时，要检查【所有 return 路径】✓
★ 验证方法：直接读 globalState 缓存看数据 ✓（比猜快得多 ✓）
```
