## 二、★★ 流式渲染：核心难点

### ② 难点

```
pi 是【一个字符一个字符】吐的 ✗ 而 MD 解析器要【完整文本】✓
全量重渲染 → 每来一个字整个气泡重建 → 闪 + 卡 ✓
```

### ③ 解法：块级切分（★ 本项目自己实现 ✗ 没用第三方 ✓）

```
按【空行】把已收到的原文切块 ✗
  · 前面的块【已闭合】✗ → 渲染一次就不再动 ✓
  · 最后一个块还在长 ✗   → 每次只重渲染它 ✓
⇒ 前面的内容稳定 ✗ 只有尾部在变 ✓✓✓

★ 代码块【不切】✗ 用 inFence 标志跟踪 ``` 的开关 ✓
  （否则代码块会被拦腰截断 ✓）
```

★ 为什么不用现成的流式库？→ `semidown` 才 0.0.3 ✗ `appemd` 不存在 ✓
**几十行自己写** ✗ 效果一样 ✓ 还少一个依赖 ✓

### ④ ★★ 两种解析器（plainParser / richParser）

```
plainParser（不带 KaTeX）
  → ★ 只用于【尾块】✓
  为什么？→ 尾块里 $ 后面还在长 ✗ 每来一个字符都重新排版公式 → 卡 + 闪 ✓

richParser（带 KaTeX）
  → ★ 闭合块 / 整段渲染 / 段结束时封尾 ✓
```

★ 实现：用 **`new Marked()` 实例** ✗ **不用全局 `marked`** ✓
（`marked.use()` 是全局单例 ✗ 一旦加了 katex 两个解析器就分不开了 ✓）

```
为什么不全转义？→ <u> / <kbd> / H<sub>2</sub>O 这些很常见 ✓ 全转义就白写了 ✓

  → 白名单内：保留 ✗ 属性再过一道（干掉 onclick / style ✓）

### ⑦ 自写三个行内扩展

```
==高亮==  → <mark>    ++插入++ → <ins>    ^上标^ → <sup>

★★ 坑（浪费了一整轮 ✗）：start() 用的正则【不能带 ^】
   start(src) { return src.search(re) }   // re = /^==…/ ✗
   → search 里的 ^ 只匹配【整个字符串开头】✓
   → 标记不在开头时返回 -1 ✗ → 扩展根本不被调用 ✓
   ⇒ 表现：段首的 ==高亮== 生效 ✗ 中间的不生效 ✓✓✓
   （用户就是靠"两张截图颜色不一致"发现这个的 ✓）

修：另做一个【无 ^】的正则专门给 start 用 ✓
```

### ⑧ 脚注

```
用 marked-footnote（1.4kB ✓）
★★ 但和"块级切分"天然冲突 ✗：
   块1: 这里有一个脚注[^1]…
   块2: [^1]: 定义              ← ★ 定义在另一个块 ✓
   → 块1 单独渲染时看不到定义 ✗ → 解析不出引用 ✓
修：★ 一旦文里出现脚注定义 ✗ → 切到【整段渲染】✓

```
