
## 二、五版黑历史

| 版本 | 做法 | 症状（用户报的） |
|---|---|---|
| ① | 只染 `.bubble` | 染色区域 = 气泡形状 ⇒ "**背景只有左侧的一根线**，有点莫名其妙" |
| ② | 染每块 `.bubble-wrap` + `margin: 0` | 一个个紫方块 + 中间黑缝（截图）|
| ③ | 把连续气泡包进一个大容器 `.compacted-zone` | ★ **用户气泡跑到左对齐 + 左右间距全丢** |
| ④ | 染 `.bubble-wrap` + 负 margin 撑满两侧 | 紫色对了 ✗ 但 AI 气泡默认 `transparent` ⇒ 紫透上来 ⇒ "**感觉还是没什么改动**" |
| ★ ⑤ | ④ + **给 AI 气泡一个实底** | ✓ 对了 |

## 三、两个关键认知（第 4 版才搞明白）

### 3.1 "左右间距"其实是气泡自己的 margin

```
#messages 的左右 padding = 0 ✗（B32 重构时就定了 ✓）
   ⇒ 左右间距 = 气泡自己的 margin：
        AI   → margin-left: var(--pi-left-gap, 3%)
        用户 → margin-right: var(--pi-right-gap, 3%)
   ⇒ ★ 所以要让背景"延伸到两侧"：
        负 margin 撑出去 + 等量 padding 推回内容
        = 视觉上多出一个 gap ✗ 内容位置纹丝不动 ✓
   ★ 成对出现是关键（负 margin 与 padding 同值 ✓）
```

### 3.2 用户气泡的特异性陷阱

```css
.bubble-wrap.user { margin-right: var(--pi-right-gap, 3%); }   /* 在后面 */
.bubble-wrap.compacted { margin-right: calc(-1 * ...); }        /* 会被它覆盖 */
⇒ 得写 .bubble-wrap.compacted.user { ... } 才赢 ✓
```

### 3.3 为什么必须给 AI 气泡一个实底

```
.bubble { background: transparent; }     /* 默认：各类型自己指定 ✓ */
⇒ 在紫色 wrapper 上 ⇒ 紫【直接透上来】
⇒ 气泡和背景融为一体 ⇒ 用户："没什么改动"✓
⇒ 修：.bubble-wrap.compacted > .bubble { background: var(--vscode-editor-background) }
   ★ 用户气泡不用管（它本来就有蓝底 ✓）
```

### 3.4 第 3 版为什么把布局搞坏了（值得记）

```
把连续的 .bubble-wrap 包进一个 <div class="compacted-zone">
⇒ ★ 换了【flex 上下文】！
   · #messages 才是那个 flex 容器（用户气泡的 align-self: flex-end 靠它 ✓）
   · 新容器默认 align-items: stretch ⇒ 用户气泡被拉成满宽并靠左 ✓
   · 同时 #messages 的子元素宽度基准也变了 ⇒ 左右间距消失 ✓
⇒ 结论：**别在渲染完之后重排 DOM 的父子关系** ✗ 用纯 CSS（负 margin）解决 ✓
```

## 四、最终实现

```css
/* 容器：整块区域染色 ✓ */
.bubble-wrap.compacted {
  background: var(--pi-compacted-bg);
  /* 撑满两侧间距 + 等量 padding 补回 ⇒ 内容不动 */
  padding-left: var(--pi-left-gap, 3%);
  margin-left:  calc(-1 * var(--pi-left-gap, 3%));
  padding-right: var(--pi-right-gap, 3%);
  margin-right: calc(-1 * var(--pi-right-gap, 3%));
  padding-top: 4px; padding-bottom: 4px;
  box-shadow: inset 3px 0 0 0 var(--pi-compacted-split-bg);  /* 左侧书脊 */
}
/* 用户气泡也要撑到右边（提特异性 ✓）*/
.bubble-wrap.compacted.user { margin-right: calc(-1 * …); padding-right: …; }
/* ★ 气泡自己给实底 ⇒ 和紫底形成边界 ✓ */
.bubble-wrap.compacted > .bubble { background: var(--vscode-editor-background, #1e1e1e); }
/* 分界线：紫底白字横条（原来用灰虚线 ✗ 用户："很难找到这条分界线"✓）*/
.compacted-split { color: #fff; background: var(--pi-compacted-split-bg); … }
```

**数据侧**（B45 已做 ✓ 这里只记要点）：

```
session-file.ts (raw 模式)  算出"未压缩起点"（最后一个 compaction 的 firstKeptEntryId）
  ⇒ 消息带 compacted: true
replay.ts                   在区段切换处插 { kind: "compactedMark", on }
chat-state.ts               记住区段 ⇒ 新建气泡带 compacted
apply.ts                    mark() 给【wrapper】加 .compacted（不是 .bubble ✓）
```

## 五、配置化（收尾）

```
pi-bridge.style.compactedBg        完整历史面板「已被压缩」区段的底色（留空 = 内置紫 ✓）
pi-bridge.style.compactedSplitBg   分界条 + 左侧书脊线的颜色（留空 = 内置紫 ✓）
pi-bridge.style.historyCollapsed   ★ 那个面板里工具块/思考块默认收起（默认 true ✓）
```

**为什么 `historyCollapsed` 要独立**：

```
主聊天页你可能希望全展开（toolCollapsed = false ✓）
但完整历史动辄上百条消息 ⇒ 不收没法看 ✓
⇒ 两个场景的合理默认值不同 ⇒ 独立开关 ✓
（实现：宿主把 --pi-history-collapsed 一起推过去；
   webview/input.ts 在 ui.historyMode 时用它覆盖 think/tool 那两个 ✓）
```

**深浅主题各一套默认值**（不能吃主题变量 ✗ 那是半透明的，叠上去等于没变 ✓）：

```
深色：#3b3054 底 / #7b68c9 分界     （第一版 #2d2a3e 与 VS Code 的 #1e1e1e 几乎同色 ✗ 看不出 ✓）
浅色：#e6dff7 底 / #8b7ac0 分界
```

## 六、教训

```
★ 这一轮我连续误解同一个描述【四次】：
    "气泡以外的区域" —— 我按"气泡之间"理解过 ✗ 按"整片区域"理解过 ✗
    按"气泡透出底色"理解过 ✗ 都不对 ✓
⇒ ★ 正确做法：**早点请用户画一张图**
   他最后画了 ✗ 一眼就清楚了 ✓
   （我已经有"用 mermaid 画图"的能力 ✗ 却没想到用它来【确认需求】✓）
   ⇒ 以后遇到形如"里面的 / 外面的 / 这块 / 那块"的指代
     ⇒ 先画个示意图让用户点头 ✗ 再写代码 ✓

★ 第二教训：**别为了"更整齐"去重排 DOM 父子关系**
    第 3 版的容器方案动机是"让背景由容器提供，逻辑更干净" ✗
    但它打断了原有的 flex 上下文 ⇒ 两个功能同时坏掉 ✓
    ⇒ 已有布局约定（谁对齐、谁撑宽）是【隐式契约】✗ 改动成本常被低估 ✓
```
