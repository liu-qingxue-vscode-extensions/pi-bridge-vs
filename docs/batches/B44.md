# B44（diff 折叠：从「hunk」到「段」）

> 起因：用户点出"edit 的折叠明显有问题 —— 整个 DIFF 作为一个单位了"。
> 结果这一处折叠改了【四版】才落地 ✗ 而每一版都是被同一个问题打回来的：
> **我把"单元"的粒度定义错了三次。**
> ★ 最后是【诊断日志】一次定死的（不是靠猜 ✗ 见第三节）。

---

## 一、四版演进（每一版为什么被否）

### v1：整个 diff 一个单元（最初的实现）

```
applyFold 数的是 container.querySelectorAll(".fold-unit")
   = [路径行(edit 的 path), hunk1, hunk2, …]
     ↑ renderPathLine 也加了 fold-unit

⇒ edit:1:0 显示的其实是【路径行】✗ 不是第一处改动
⇒ 用户："只要有一个数字，马上全部展开"（因为计数里混了路径行 ✓）
```

### v2：按 patch 的 hunk 切

```
让 hunk 用 .fold-hunk ✗ applyFold 有 hunk 时只数 hunk
⇒ 用户实测截图打回来了：
   那个文件有【5 处改动】✗ 但 patch 里只有【1 个 @@】（diff 算法把距离近的合并了）
   ⇒ 按 hunk 折 = 只有 1 个单元 = 全有全无 ✓
★ 用户原话："一个 edit 可以传入多次，在多个不同的地方做修改…
            假如它修改了三个地方，对于这一个块里，它应该是出现三个单元"
```

### v3：按"改动块"切（连续 - 行 + 紧接着连续 + 行）

```
★ 这才对上了用户说的"一处红绿色 = 一次修改"（我一开始误解成"一个 hunk"了）
⇒ 每个改动块一个 .diff-change（fold-change）
```

### v4（最终）：按"段"切 = 上下文 + 改动

```
★ v3 还不够 —— 用户实测截图发现：
   "它这个原文内容在乱跳 ✗ 你可以看它的行号…红绿灯倒是全都听规矩"
   截图证据：10 → …（已折叠 2 处）→ 15 → 16 → 21 → 22
            ★ 中间 11-14（改动行）被折了 ✓ 但 15/16 是上下文 ⇒ 看起来"跳到 15" ✓

★ 根因：只折【增删行】⇒ 它前后的上下文行【接在一起】⇒ 行号看起来断裂
⇒ 单元必须【连它前面的上下文一起折】✗ 剩下的内容才依然连续 ✓
   · 段 = [攒着的上下文行] + [一处改动]
   · 上下文行 ⇒ 当前段到此结束（后面的上下文若又遇到改动，就是新段的开头）
   · 尾部上下文（最后一处改动之后）不属于任何段 ⇒ 一直显示 ✓
```

## 二、★ 我写错的那一处（日志一次定位）

```ts
// v4 第一版（我写错的）：
if (kind === "ctx") {
    if (!seg) pending.push(line);
    else seg.appendChild(line);   // ★ 把上下文"塞进"当前段 ⇒ 整段吞掉所有 ⇒ 永远 1 个段
    continue;
}
```

**诊断日志**（临时加在 applyFold 里）：

```
[fold] tool=edit collapsed=false segs=1 units=1 rules={"bash":[2,1],"read":[1,1],…}
                              ↑★★ 应该是 5（5 处改动）⇒ 一眼看出段没切开
```

**改成**（上下文行结束当前段）：

```ts
if (kind === "ctx") {
    seg = null;              // ★ 当前段到此为止
    pending.push(line);      // 后续上下文先攒着（若又遇到改动就是新段的开头）
    continue;
}
if (!seg) {
    seg = document.createElement("div");
    seg.className = "diff-seg fold-seg";
    dumpPending(seg);        // 攒着的上下文当这段的开头
    host2().appendChild(seg);
}
seg.appendChild(line);
```

**验证**：用户"OK，完美"✓

## 三、★ 方法论：诊断日志要给"可判定的事实"

这一处折叠改了四版 ✗ 前三版都是**我猜**（"应该是 hunk 吧""应该是改动块吧"）✗ 都被打回。
第四版加了一行日志：

```ts
log.info(`[fold] tool=${tool} collapsed=${collapsed} segs=${segs.length} units=${units.length} rules=${JSON.stringify(rules)}`);
```

**为什么要打这几个**：

```
segs / units   → 单元切出来几个（切错了一眼看出：期望 5 得到 1）
collapsed      → 状态是不是反的（"点了没反应"可能就是状态错 ✗ 不是折叠错）
rules          → 规则有没有读到（用户可能把配置删空了 ⇒ rules={} ⇒ 全折 ✗ 看起来也像"没折"）
tool           → 万一调用的工具名不对（比如 dataset.tool 是空的 ✓）
★ 这四个字段把"可能的原因"全枚举了 ⇒ 一条日志就能定位 ✓
```

**和 B42 那次"调用栈定位启动真凶"是同一个套路**：
不要让看日志的人继续猜 ✗ 要让日志里直接写着答案 ✓

## 四、最终结构

```html
<div class="diff-hunk">                      ← 分组容器（不参与折叠计数）
  <div class="diff-hunk-head">@@ -1,28 +1,28 @@</div>   ← 坐标说明（一直显示）
  <div class="diff-seg fold-seg">            ← ★ 单元 1 = 上下文 + 改动
    <div class="diff-line ctx">…</div>×4
    <div class="diff-line del">…</div>×4
    <div class="diff-line add">…</div>×4
  </div>
  <div class="diff-seg fold-seg">            ← ★ 单元 2（段间有虚线分隔）
    …
  </div>
  <div class="diff-line ctx">…</div>         ← 尾部上下文（不属于任何段）
</div>
```

**折叠规则**：`edit:1:0` ⇒ 只显示第 1 段（含它前面的上下文 ✓ 行号连续 ✓）
`edit:0:0` ⇒ 全折 ⇒ 提示 "…（已折叠 5 处改动 · 点顶栏展开）"

**CSS**（`media/css/tool.css`）：

```css
.diff-seg { border-top: 1px dashed …; }              /* 段之间的分隔（用户要的"分割"）*/
.diff-hunk > .diff-seg:first-of-type { border-top: none; }   /* 第一段不要分隔线 */
.diff-seg.fold-hidden { display: none; }             /* 被顶栏折起来的段 */
```
