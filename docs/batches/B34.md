## 三、★★ 拖拽的实现演进（本轮最有价值的部分）

### ③ 第一版：把 dragover / drop 挂在【每个按钮】上 ✗

```ts
b.addEventListener("dragover", (e) => {
    if (!drag || drag.id === item.id) return;   // ★ 拖动源自己直接跳过
    e.preventDefault();
    ...
});
```

**结果：拖动成功率很低** ✗（用户报的 ✓）

**根因**：
```
你拖起来的时候，鼠标【正下方就是拖动源自己】✗
  → 那个位置既不 preventDefault ✗ 也不接 drop ✓
  → 必须"挪到别的按钮上"才能落 ⇒ ★ 成功率当然低 ✓✓✓
```

### ④ 第二版：改成【容器级】✓

```ts
function wireContainer(el, parentId, horizontal) {
    el.addEventListener("dragover", (e) => {
        e.preventDefault();      // ★ 容器级：整个区域都能落 ✓
        const slot = findSlot(drag.others, pos);
        if (slot === drag.slot) return;   // ★ 没变就不重画
        drag.slot = slot;
        paintSlot();
    });
    el.addEventListener("drop", (e) => { ...提交... });
}
```

★ 挂载点：竖条 `#cmd-rail-list`（纵向 y ✓）+ 弹层 `.rail-pop`（横向 x ✓）
★ 按钮上只留 `dragstart` / `dragend` ✓

### ⑤ ★★ "不稳定"的根因（用户自己诊断出来的 ✓）

```
用户原话：
  “知道为啥不稳定了 ✗ 这个动画应该是前后上下移动过去就放在那儿不动 ✗
   直到我的判定离开改变了它才返回原位 ✗ 吧？”✓
```

**根因链**（和用户说的一模一样 ✓）：
```
元素被 transform 平移 → 鼠标相对它的位置变了
  → 浏览器补发 dragleave → 我们把标记清了
  → 元素弹回原位 → 鼠标又回到"前半" → 再加标记 → 再平移
  ⇒ ★ 无限循环 ✗ 看着就是抖 / 不稳 ✓
```

**修法**：
```
① ★ 不再监听 dragleave ✗（元素一平移它必然触发 ✓）
   真正的清理点改成：落点变化时（paintSlot 开头 ✓）+ dragend ✓
② ★ "已经定了就不重算"✗ 只有落点真的变了才重画 ✓
```

### ⑥ ★★ "动画与实际不统一"（用户报的 ✓）

```
用户原话：
  “你这个动画和实际效果不统一 ✗
   明明不会进入他俩之间 ✗ 他俩仍然让开位置”✓
```

**根因**：
```
判定用 getBoundingClientRect() ✗ 而它【会反映 transform】✓
  → 元素一让开 8px ✗ 判定基准跟着偏 ✓
  → 鼠标指的地方 和 系统判定的地方 就错位了 ✓
```

**修法（★ 关键：语义要与后端一致 ✗）**：
```
后端 moveCommand 的逻辑是【先把源摘出来 ✗ 再插进去】✓
前端要从同一个语义出发：

① dragstart 时【快照】同级其他按钮的【未变换】中点 ✗ 之后一直用它 ✓
② ★ 从快照里【排除拖动源自己】✗（因为后端也是先摘出来 ✓）
③ 鼠标坐标跟快照比 → 得到"插到第几个之前"✓
④ 动画画的空位 = 那个索引的位置 ✓  ★ 两边同源 ✗ 就不会不一致 ✓
```
