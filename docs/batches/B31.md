## 二、★★ 配置作用域机制（本轮的技术地基）

### ④ 问题

```
用户要的：“技能面板相关行为控制放进【设置面板】里 ✓ 放到【行为】组里 ✓”
★ 但那个设置面板渲染的是【pi 的 settings.json 字段】✗
★★ 而"技能单击行为"是【我们扩展自己的 VS Code 配置】✓
⇒ 两套东西要能在同一个面板里共存 ✓
```

### ⑤ 解法：给字段加 `scope`

```ts
export interface FieldDef {
    key: string;
    /**
     * "pi"     = pi 的 settings.json（默认 ✓）
     * "vscode" = VS Code 工作区配置（pi-bridge.* ✗ 我们自己的 ✓）
     */
    scope?: "pi" | "vscode";
    …
}
```

★ 读分流（`settings-post.ts` ✓）：
```ts
if (f.scope === "vscode") {
    value = vscode.workspace.getConfiguration().get(f.key) ?? f.fallback ?? "";
} else {
    value = getByPath(all, f.key) ?? …;
}
```

★ 写分流（`main.ts` 的 saveSettings ✓）：
```ts
// ★ 用前缀判断就够 ✗ pi 的字段不可能以 pi-bridge. 开头 ✓
if (k.startsWith("pi-bridge.")) {
    await vscode.workspace.getConfiguration().update(k, v, ConfigurationTarget.Global);
    continue;
}
```

⇒ ★ 配置项同时出现在【我们的设置面板】和【VS Code 原生设置】里 ✓

### ⑦ 阶段 2：右键菜单 + 只读控制

```
【右键】★ 直接跳转 ✗ 不做内嵌下拉 ✓
   用户：“查看内容是下拉这个东西 ✗ 下拉这个东西不要啊”✓
   · 自定义技能 → 「查看 / 修改内容…」→ 打开【磁盘文件】✓ 可改可存 ✓
   · 非自定义   → 「查看内容（只读）…」→ 打开【未命名文档】✓
   · 「在磁盘上定位…」→ revealFileInOS ✓
   · 「隐藏（不显示）」→ 写进 pi-bridge.skills.hidden ✓
   · 删除（仅自定义 ✗ 红色 ✓）

★★ 只读怎么实现？—— 三条路 ✗ 选了最省事又安全的 ✓
   A. ★ 未命名文档（选它 ✓）
      内容一样 ✗ 但它是新文档 → 保存必须"另存为"✗ 物理上覆盖不到原文件 ✓
      优点：零成本 ✓ 标题显示 Untitled-1 一眼可辨 ✓
      缺点：不是编辑器原生只读标志（但效果等价 ✓）
   B. FileSystemProvider（真只读 ✓ 编辑器会显示锁标 ✓）
      要写几十行 ✗ 多一套 URI scheme ✗ 收益不大 ✓
   C. 直接打开磁盘文件 → ✗ 没有"设只读"的 API ✓

【★ 为什么"修改"要走原生编辑器？】（用户定的 ✓）
   “这个文件的内容是我们暂存还是临时去拿呢？
    如果临时去拿还能理解 ✗ 我这边修改完保存好了 ✗ 用到的就是最新的”✓
   → showTextDocument(Uri.file(path)) 打开的就是【磁盘那个文件】✓
   → Ctrl+S 即落盘 ✗ 无暂存 / 无同步问题 ✓✓✓

【★ 只读技能的防护有两道】
   ① 前端不给入口（右键菜单里没有修改/删除 ✓）
   ② 宿主端再挡一次（deleteSkill 里 if (!hit.mine) 拒绝 ✓）
   示例：「删除」按钮只对 mine 渲染 ✗ deleteSkill 又查一次 ✓
```
