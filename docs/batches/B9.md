## B9：拆 webview TS（965 行 → 14 个模块）

### ① 为什么必须拆

```
965 行单文件 + 14 个散落的 let（跨模块共享状态）✗
· 改"顶栏电池"要在 965 行里找 → 每次都得全文搜索 ✗
· B8 一轮里连踩 2 个坑（package.json 重排 / keybinding 覆盖）就是文件太大的直接后果 ✗
· 原文件还有 300 多行根本没有 tsc 在检查（被 exclude 掉 ✗）→ 类型错误要到运行时才爆
```

### ② ★ 关键难点：ES 模块的 `let` 不能跨模块共享

```
在 A 模块 `import { x }`，拿到的是一份【快照引用】✗
B 模块里 x = ... 重新赋值【不会】反映到 A ✗（绑定是模块局部的）
```

**解法**：把所有可变状态放进**一个对象** → 各模块拿到的是**同一个对象**的引用 ✓
```
src/webview/state.ts        export const ui = { bubble, pendingEl, userAborted, … }
用法：ui.bubble = xxx       （跨模块共享同一个对象 ✓）
```

> ★ 同时明确了**两种状态的界线**：
> - **权威状态**（气泡内容、通知列表）在**插件端** `ChatState` —— webview 销毁也不丢 ✓
> - **UI 过程状态**（"当前正在拼哪个气泡"）在**本文件** —— 纯前端细节，重放快照时会被重置 ✓

### ③ 模块结构（14 个文件，单向依赖 ✓）

```
src/webview/
├─ index.ts        31 行   ★ 入口：只做"绑定交互 + 绑定消息 + 报 ready"
├─ apply.ts       295 行   ★ 宿主消息分发（styleVars/snapshot/patch/…）
├─ noticeboard.ts 207 行   通知面板（顶栏下拉 · B8）
├─ tool.ts        180 行   工具气泡（外框 / 参数键值对 / 结果 / 状态）
├─ notices.ts     121 行   消息流里的提示（重连气泡 + 异常提示）
├─ input.ts        99 行   输入区（发送 / 中断 / 高度自适应 / 样式变量）
├─ bubbles.ts      83 行   气泡基础（滚动 / 建气泡 / 折叠头 / 占位三点）
├─ topbar.ts       68 行   顶栏（花费 / out / cache / 电池）
├─ state.ts        67 行   ★ 所有可变 UI 状态（单对象）
├─ format.ts       45 行   纯格式化工具（fmtNum / fmtCost / shortenPath / …）
├─ dom.ts          42 行   ★ 所有 DOM 引用（只读 const）
├─ thinking.ts     39 行   思考气泡
├─ segments.ts     31 行   「内容段 → 气泡」分发（text / thinking）
└─ vscode-api.ts   27 行   ★ acquireVsCodeApi 单例（只能调用一次 ✗）
```

**依赖层级**（严格单向 ✓）：
```
format · dom · state · vscode-api         ← 叶子（不 import 任何自家模块）
      ↓
bubbles                                    ← 基础渲染
      ↓
thinking · tool
      ↓
segments（依赖 bubbles + thinking）
notices · topbar
      ↓
input · noticeboard
      ↓
apply（分发一切）
      ↓
index（只启动）
```
