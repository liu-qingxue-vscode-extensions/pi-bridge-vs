## 第一部分：技术答案（已实测验证 ✓）

### 1.1 VS Code 的"弹窗"到底有什么

```
实测：grep node_modules/@types/vscode/index.d.ts

window.showInformationMessage / showWarningMessage / showErrorMessage
    → 顶部或模态提示 ✗ 【只能带几个按钮】✗ 放不了任何输入框 ✓

window.showQuickPick
    → 快速选择 ✗ 单选或多选 ✓ 可以带每项的 label/description/detail ✓
    → ★ 这就是"从有限集合里挑一个" ✓

window.showInputBox
    → 一行输入 ✗ 可以带 prompt / placeHolder / validateInput ✓
    → ★ 这就是"自由值" ✓

window.showOpenDialog / showSaveDialog
    → 文件 / 目录选择器 ✓

window.createWebviewPanel
    → ★★ 自己开一个面板 ✗ 这是【唯一】能放任意表单的东西 ✓

grep "showForm|showDialog|createDialog"  →  【0 个】✓
```

### 1.2 ⇒ 三条结论

```
① ★ "弹窗里放一个多字段表单" ✗ 原生【做不到】✓
   （VS Code 不给扩展这种能力 ✗ 内部功能才有 ✓）

② ★★ 要"一次填完"✗ 只能自己开 WebviewPanel ✓
   —— 而 WebviewPanel 在 VS Code 里【永远是编辑器区的一个标签页】✗
      没有真正的浮动窗口 ✓
   —— 但可以用 ViewColumn.Beside 从旁边挤出来 ✗ 视觉上"像弹窗"✓

③ ★★★ 绝妙同构 ✗：
      原生弹窗的形态   = 一次问一个问题（QuickPick / InputBox ✓）
      TUI 喂参数的方式 = 一次问一个问题 ✓
      ⇒ ★ 串行弹窗【零 UI 代码】✗ 而且最贴合 TUI 语义 ✓✓✓

   ★ 但串行的缺点 ✗：
      · 不能回退（第一个答错要整条重来 ✓）
      · 看不到最终命令长什么样 ✓
      · N 个参数就是 N 次弹窗 ✗ 有点烦 ✓
```

## 第二部分：图标（用户之前问过 ✗ 这次答）

```

① codicon —— VS Code 自带的图标字体（500+ 个 ✓）

   缺点：文字→图标名需要映射表 ✓

② ★ Emoji（推荐 ✓）
   直接填 🚀 📁 ⚙️ ⭐ 🔍 ✗ 零映射 ✗ 零成本 ✓
   用户想要"目录"→ 自己填 📁 就行 ✓

④ Nerd Font ✗ 要额外打包字体文件 ✗ 不值 ✓

⇒ ★ 三者共存 ✗ 优先级：
     填了 emoji   → 用 emoji ✓
     填了 codicon名 → 用 codicon ✓
     都没填       → 用 label 首字 ✓
```

## 第三部分：★★ 用户的设计（逐条还原 ✓ 待核对）

### 3.1 配置流程：点「＋」之后

```
点「＋」→ 进入【配置独立页面】（VSCode 编辑器区的 WebviewPanel ✓）

从上到下依次填 ✗：
 ┌───────────────────────────────────────────────┐
 │ 1. 语义      名字 / 悬停提示 / 图标            │ ← 最基础的三个属性
 │ 2. 类型      ○ 按钮   ○ 收纳                   │ ← type 决定后面完全不同
 │ 3. 命令      斜杠命令                          │
 │ 4. （收纳才有）命令预设 + 强制开关             │
 │ 5. （按钮才有）参数列表（0..N 个）             │
 │ 6. （按钮 + 有参数）输入方式：弹窗 / 独立窗口  │
 └───────────────────────────────────────────────┘
```

### 3.2 type = 收纳

```
★ 收纳器不执行命令 ✗ 它是个【分组】✗ 点开横向弹出一排按钮 ✓
★ 点收纳器 → 横向容器弹出来 ✗ 里面最后一项【仍然是「＋」】✓
★★ 但那个「＋」里 type 【预设为按钮 ✗ 不可修改】✓
   —— 用户原话：“这里就不能再加收纳器了”✓

★ 收纳时可以【预设一个命令】✗ 并给它一个开关：
   ○ 强制 → 后面加进来的命令【锁死】✗ 必须是那个命令 ✓
   ○ 软   → 只是预填 ✗ 可以改 ✓
   用户原话：“你这个命令是强制还是软的 ✗
              如果加上强制 ✗ 那么后面的命令就锁住 ✗ 必须是那个命令”
```

### 3.3 type = 按钮

```
★ 按钮要问：要不要参数？
   不要参数 → 零个参数 → 点一下【直接注入命令】✓（最简单 ✓）
   要参数   → 点「＋」逐个加参数 ✓
```

### 3.4 参数（b1 ✗ 三种类型）

```
每个参数要选 type ✗：
  ① 固定值      → 这个位置恒等于某段文本 ✓
  ② 有限值可选  → 下拉框 ✗ 从几个里选一个 ✓
  ③ 任意值      → 输入框 ✓

★ 用户补充的自动识别 ✗：
   “你的可选内容如果只有一个的话 ✗ 自动识别成固定参数也行”✓
   ⇒ ★ 有限值选项只有 1 个 → 自动降级成固定值 ✓

★ 任意值也可以限定一下 ✓：
   “最后任意值也可以限定一下 type ✗ 假如说数字”✓
   ⇒ 任意值可以有【子类型】✗ 文本 / 数字 / …（至少先做校验 ✓）
```

### 3.5 输入方式（b2 ✗ 可配置）

```
★ 用户原话：“输入方式可配置 ✗
   在创建第一个需要传参的参数之后出现，
   或者常驻但在满足条件后启用的一个选择框？”

两种方式 ✗：
  ① 弹窗选择（串行 ✗ 用 VS Code 原生 QuickPick + InputBox ✓）
  ② 独立窗口输入（一次填完所有参数 ✓ 我们自己的 WebviewPanel ✓）

★★ 用户要求的警告 ✗：
   在配置【第二个参数时】警告 ✗：
   “你有多个参数 ✗ 弹窗会连续弹连续弹窗 ✗ 可能影响体验 ✓
    建议这种情况下通过预设穷举参数直至只剩一个（或无）参数 ✗
    收纳可以解决穷举的多个按钮 ✓
    或者选择独立窗口输入 ✗ 一次性填写所有参数”✓

⇒ ★★★ 这条洞察很关键 ✗ 它把三个东西串起来了 ✓：
   弹窗的缺点（多次弹）→ 用【穷举 + 收纳】消掉 ✓
                       → 或者用【独立窗口】消掉 ✓
   ★ 也就是说：收纳器 = 穷举的产物 ✗
     用户手动把常用组合做成一个个按钮 ✗ 收进一个收纳器 ✓
     这样点一次就完事 ✗ 不用弹任何窗 ✓✓✓
```
